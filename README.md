# AGLDWG PID Register - configuration

This repository configures an application stack of [Prez](https://prez.dev) and a back-end RDF database, currently [Fuseki](https://jena.apache.org/documentation/fuseki2/) to deliver data in the AGLDWG's [pid-register-data]() repository as Linked Data online.

There are two main registers of Linked Data objects:

- `pids`: `dcat:Catalog` / `dcterms:hasPart` / `pid:PID`
- `orgs`: `schema:DataCatalog` / `schema:hasPart` / `schema:Organization`


PrezUI is generated by `create-prez-app` with a small repository-owned AGLDWG
theme layer. Prez uses fixed prefixes from `prez/config/prefixes` for stable
links and serializations across restarts.

## Local Fuseki

Install Docker with Compose, [Task](https://taskfile.dev/), and [kgm](https://kurrawong.github.io/kgm/), then:

```bash
cp docker/.env.example docker/.env
# replace the two local password placeholders; PIDDATA_USERNAME defaults to piddata
task stack:build
task stacu:up
task data:sync
task test:catalogues
```

Open PrezUI at <http://localhost:3000/catalogues>, Prez at <http://localhost:8000/catalogues>, and Fuseki at <http://localhost:3030/>.

## Remote SPARQL endpoint

Set `SPARQL_ENDPOINT` in `docker/.env` to the complete query URL. Leave `SPARQL_USERNAME` and `SPARQL_PASSWORD` blank for anonymous access, or set them for HTTP basic authentication.

```bash
task build:remote
task up:remote
```

Remote mode does not start Fuseki. Both modes use the `catalogues → catalogues → items` endpoint structure. Models, Organisations, PIDs and Validators appear at the root. Their directly included resources appear under each root's `catalogues` route; the four PID subcatalogues then expose their PID records as items.

## Azure Functions development

The Prez API can also run through Azure Functions Core Tools, with PrezUI still
served from its container and proxying `/api` to port 7071:

```bash
task functions:build
task functions:dev
```

Use `task functions:down` to stop the Functions-mode UI. Copy
`prez/local.settings.example.json` to `prez/local.settings.json` and supply the
same SPARQL settings used by the selected Fuseki or remote endpoint.
